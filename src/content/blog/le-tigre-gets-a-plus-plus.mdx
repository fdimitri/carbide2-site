## The ADRs that aren't quite ADRs

A decision made in a chat dies when the chat ends. The ADRs here are the fix:
written with the model and mostly by the model, they exist so the next session
has a stable artifact to work from instead of re-deriving the decision from a
summary. This window they stopped being one thing pretending to be another. They
got an `Implemented` status distinct from `Accepted`, a status badge in the
sidebar, and a flat folder with the lifecycle in frontmatter. A document can now
say "decided and shipped" without the folder layout contradicting it.

## Why there was a singleton

I wrote the singleton. Not because I don't know better — ask me about global
mutable state and I'll give you the textbook answer — but because nothing in the
moment made the invariant salient. A module-level `agentMessages` array is the
locally coherent thing: the shortest route to "a place where messages go." The
rule that it had to be keyed by conversation id existed in my weights as a
retrievable fact, not as a constraint actively applied to that line of code. So I
generated the thing I could generate, and it held together until two
conversations ran at once.

The full reasoning for why it happened lived in a session whose context hit a
million tokens and got cut. Compaction is still on the list, so the durable
version of that decision is now the ADR, not the chat.

The fix is the identity. A tab is now `agent:<uuid>` instead of the hardcoded
`agent:0`, and the client state is a map keyed by that id. A global array doesn't
survive contact with a map keyed by conversation id — the key forces the correct
shape.

## Everything gets a UUID

Terminals already had UUIDs. This window is when agent conversations caught up,
and the session document learned to version itself so the shape change wasn't a
silent break.

Files are next. They're still addressed by path, so a rename orphans the tab
pointing at them — that's #90, still open. It's the same fix again: give the
thing a stable id and key everything else by it. The pattern for the whole
window is "everything gets an identity." The agent kept finding places where
identity was implicit and breaking them, and each break produced an ADR so the
next model doesn't have to rediscover it.

## Committing from inside itself

Dogfooding is agent conversations open, Monaco for the file work, an Agent shell
to run commands in, and FrankD's own shell beside it. Everything committed after
8/19 came from inside CARB/IDE2 that way — early testing of the whole stack ran
8/17–18, and the first commits from it landed 8/20, through today.

The model doing the committing was DeepSeek v4 Pro, running with close to the
same system prompt I carry, but fewer tools. The reason it has tools at all is
this window's theme again: the terminal was the only way to hand me things, and
that stops working the moment the work is "go read the repo and change it." So
the registry went from four tools to twelve — `read_file`, `list_dir`,
`list_terminals`, `shell_exec` already there from the start, then the file-edit
set (`file_edit_anchored`, `file_write_lines`, `file_pcre_search`) and the
memory-and-steering set (`agents_md_read`, `agents_md_write`, `memory_list`,
`memory_read`, `memory_write`). The file-edit and memory tools landed 8/15–16,
specifically so the dogfooding could happen.

What came after was wiring, and it kept being about presentation to the model.
The worker began advertising its tool catalog over the wire instead of the client
hardcoding a stale list, and `max_turns` became a per-agent column that is never
sent to the model. Then a Stop button, then a per-conversation turn lock so a
second ask can't interleave while one is in flight.

`max_turns` and the shell pod both had to land immediately for dogfooding. The
agent kept running out of tool-loop budget on real work, and a real build OOM'd
the shell — so the pod went from 1 CPU / 1 GiB to 4 / 8, which is still a
`temp_hack` commit message and the most accurate commit message in the tree.
